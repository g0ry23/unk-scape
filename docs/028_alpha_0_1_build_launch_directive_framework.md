## 3. ALPHA 0.1 POSITION

Alpha 0.1 is the first controlled production proof that Foundation architecture can support the core gameplay loop.
Alpha 0.1 must establish: The game can boot. The namespace is controlled. The loop runs. The player can move. The world can load. A resource can be gathered. Rewards can be granted. XP can be granted. Inventory can persist. Saves can reload. Feedback can be seen. The system can be tested.
Alpha 0.1 exists to prove the spine. Everything else waits.

## 4. CORE ALPHA LAUNCH RULE

Build the smallest complete Foundation loop before building anything larger.
The smallest complete Foundation loop: 1. Create or load basic world. 2. Create or load basic character. 3. Spawn player. 4. Move. 5. Interact with resource node. 6. Gather with timing. 7. Receive item. 8. Gain XP. 9. See feedback. 10. Save. 11. Reload. 12. Confirm progress persists.
If a feature does not directly support that loop, it is not Alpha 0.1 priority.

## 22. ALPHA 0.1 BUG BLOCKERS

S0 Critical Blockers: Game does not boot. Save data is lost. Load fails. Player cannot spawn or move. Inventory deletes rewards. XP corrupts. Game loop crashes. Save corruption is silent.
S1 High Blockers: Resource interaction fails. Gathering grants no item or XP. Rewards do not save. Rapid clicking duplicates rewards. UI gives no feedback. Character/world link missing.
S2 Medium: UI confusing, camera hides target, inventory unclear, save feedback unclear, debug insufficient.
S0 and S1 block acceptance. S2 must be fixed before milestone unless Greg approves deferral.
